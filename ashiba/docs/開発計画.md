# 今後の開発計画（2026-10 時点）

## 1. いまの到達点

- 計画エンジン（Python）: 平面・立面割付、法規12項目、構造計算の下書き、数量、設置届一式、付帯設備（階段・開口部・ステージ・昇降機・ブラケット・朝顔）、敷地高低差。テスト1248本。
- Archicad 側（Archicad 30 ＋ Tapir 1.7.0 で実機確認）:
  - 足場ライン（1辺＝1オブジェクト）を平面に配置。3Dは実寸（コマ・爪・踏板の逃げ）、線表示モードあり。
  - 立面図は断面図ビューポイントで作り、サブセット「仮設足場」のレイアウトに1枚で配置。
  - 平面のホットスポットでスパンを編集し、`read_back_spans.py --apply` で入力に戻して解き直せる。
  - モデル表示オプション部品（平面の詳細／単線・注記の有無・3D表現）。メートル／インチの切替。
- 実機で分かった Tapir の制約（設計の前提）:
  - 断面の作成・要素の削除は**平面図が前面**のときだけ通る（`ChangeWindow` で切り替える）。
  - 断面のナビゲータ項目とレイアウトのサブセットは API で消せない（断面は要素 GUID で消す）。
  - 文字は**現在のウィンドウ**にしか置けない。ただし `ChangeWindow` で断面図を開けば、そこに `CreateTexts` で置ける（2026-10-17 確認）。
  - `CreateLayoutSubset` は作っても ID を返さないことがある（名前で引き直す）。
  - 断面の横軸は切断線の向きへの射影、縦軸は標高。断面を消すと中の注記も消える。
  - 図面の大きさは比率 `scale` で決まる（`drawingScale` は縮尺名だけ）。図面の削除はそのレイアウトが前面のときだけ。
  - スラブや足場部品の検索も、平面図が前面でないと見つからない（各スクリプトの冒頭で平面図へ）。
  - 図面の切り抜き枠は用紙の絶対座標、中身は pos＋モデル×縮尺。Tapir は pos＝position−枠の最小角×比率（比率＝元の縮尺/置く縮尺）。
  - 要素の平面の外形は Archicad 本体の `API.Get2DBoundingBoxes` で測れる（Tapir には無い）。`MoveElements` で動かせる。
  - 断面要素（CutPlane）と断面のナビゲータ項目は API で対応が取れない（控えの GUID で消す）。
  - Archicad が操作中だとアドオンの命令が時間切れになる（IsAlive は返る）。読む命令だけ再試行する。
  - 長時間の作業のあと、図面の生成（断面の図面化・レイアウトへの配置）が CPU 0% のまま止まることがある（2026-10-18、起動から約3時間後から5回）。進行表示の「更新を中止」、画面のスクロール、待っている側の接続を切ると動き出す。止まっている間はアドオンの命令がすべて待たされる。UpdateDrawings を呼ばない・待つ間に IsAlive を送る、では防げなかった。Archicad をアプリごと再起動（14:27）したあとはスモーク7件が約6分で全部通った。長時間（約3時間以上）連続で使うと起きる。
  - 図面を作る命令（CreateDrawings 等）は30m棟で60秒を超えるので、待ち時間を延ばしている（作る命令は再試行しない）。
  - Tapir パレットは ~/Documents/Tapir/custom-scripts の直下だけを一覧にする（`uv run --script 入口 --port 番号`）。Archicad から起動したプログラムはデスクトップを読むのに macOS の許可が要り、許可待ちで黙って止まる。

## 2. 方針

1. **正は Python、図は Archicad の流儀で**。割付・数量・法規の答えは Python が持ち、図面は Archicad のビューポイント・レイアウト・注記で作る。部品の中だけで完結する2D作図は減らしていく。
2. **ツールバー1回で提出図書がそろう**ことを目標にする。平面・立面・詳細のレイアウトと PDF まで。
3. **入力は Archicad の中で**。デスクトップの JSON を手で編集する運用を卒業する。
4. 各段階は**実機で作って確かめてから**完了とする（小型入力 `examples/dev/` ＋ 30×20m）。
