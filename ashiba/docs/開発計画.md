# 今後の開発計画（2026-10 時点）

## 1. いまの到達点

- 計画エンジン（Python）: 平面・立面割付、法規12項目、構造計算の下書き、数量、設置届一式、付帯設備（階段・開口部・ステージ・昇降機・ブラケット・朝顔）、敷地高低差。テスト996本。
- Archicad 側（Archicad 30 ＋ Tapir 1.7.0 で実機確認）:
  - 足場ライン（1辺＝1オブジェクト）を平面に配置。3Dは実寸（コマ・爪・踏板の逃げ）、線表示モードあり。
  - 立面図は断面図ビューポイントで作り、サブセット「仮設足場」のレイアウトに1枚で配置。
  - 平面のホットスポットでスパンを編集し、`read_back_spans.py --apply` で入力に戻して解き直せる。
  - モデル表示オプション部品（平面の詳細／単線・注記の有無・3D表現）。メートル／インチの切替。
- 実機で分かった Tapir の制約（設計の前提）:
  - 断面の作成・要素の削除は**平面図が前面**のときだけ通る（`ChangeWindow` で切り替える）。
  - 断面のナビゲータ項目とレイアウトのサブセットは API で消せない（断面は要素 GUID で消す）。
  - 文字は**現在のウィンドウ**にしか置けない。ただし `ChangeWindow` で断面図を開けば、そこに `CreateTexts` で置ける（2026-10-17 確認）。
  - `CreateLayoutSubset` は作っても ID を返さないことがある（名前で引き直す）。

## 2. 方針

1. **正は Python、図は Archicad の流儀で**。割付・数量・法規の答えは Python が持ち、図面は Archicad のビューポイント・レイアウト・注記で作る。部品の中だけで完結する2D作図は減らしていく。
2. **ツールバー1回で提出図書がそろう**ことを目標にする。平面・立面・詳細のレイアウトと PDF まで。
3. **入力は Archicad の中で**。デスクトップの JSON を手で編集する運用を卒業する。
4. 各段階は**実機で作って確かめてから**完了とする（小型入力 `examples/dev/` ＋ 30×20m）。
