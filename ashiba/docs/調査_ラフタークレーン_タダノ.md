# タダノ ラフテレーンクレーン（ラフター）の機種・寸法・性能表（調査 2026-11-01）

> 2026-11-01 のラフタークレーンの調べ（利用者の指定「ラフタークレーンも追加して種類も増やして　アウトリガーを位置変更できるようにして　クレーンの平面は詳細図レベルにして　性能表とリンクさせてね」）。文中の research5/… は調べたときの一時置き場でリポジトリには残っていない（資料は出典の URL から取り直す）。表は src/ashiba/crane_tables.py、寸法は crane.py の MODELS に入れた。

- 値ごとに出典記号（下の「出典一覧」）と PDF の頁（**PDF のページ番号**。印刷の頁番号ではない）を付けた。
- 「公表」= メーカーの仕様書・データシートに数値で書いてある値。「図上」= 寸法図に書いてある寸法が**何の寸法か**を図から私が判断したもの、または図から測ったもの（今回は測った値は無い。判断が入るものだけ「図上」と書く）。「計算」= 公表値どうしの引き算。
- 表は頁を pdftoppm で画像にして Read で見て、列（ブーム長さ）と行（作業半径）を数えて確かめた。数値は文字のある PDF は語の位置（pdftotext -bbox）で列に割り付け、画像と突き合わせた。画像だけの PDF（16t）は 250dpi の画像から目で写した。読み方の注意は末尾「読み取りの方法と注意」。

図上の判断の中身:
- **反対側の脚**: 平面図では上の段と下の段の脚の前後位置がずれて描かれ、下の段の寸法（例 25t 3,265／3,415）が側面図の寸法と同じ。左右のアウトリガビームが箱の中で前後にずらして納まるためと読める。ずれの量（195〜310）は図の脚の脇の寸法と、上下の段の差が一致する。
- **フートピン**: 側面図で、ブーム長さの寸法（「最小 9,350 最大 30,500」等）の端から下ろした一点鎖線が小さな円（ピン）を通り、旋回中心からその線までの寸法（25t 2,600、60t 2,950、70t 3,000、100t 2,900、16t 2,020、13t 1,138）が引かれている。高さは、その円の高さに引出線がある寸法（25t 3,435、16t 3,210、13t 2,765、60/70/100t 3,748）。拡大画像で確認したのは 13t・16t・25t・60t・70t・100t。
- **高さの基準**: 右側の高さ寸法（例 16t の 1,663・2,652・3,210・3,431）は、タイヤの接地面より 283 下（ジャッキを伸ばした時のフロート下面）を基準に描かれている。16t で「全高 3,150（走行時の最高点＝先端シーブ上）」と「3,431（同じ点）」の差 281 ≒ 283。よって走行時の高さは引き算（表の「計算」）。作業時（タイヤが浮くまでジャッキを伸ばした状態）の地面からの高さは図の値のまま、と読める。
- 既存の CraneModel の目安値との違い（参考）: 25t の piv_b 1,300・piv_h 2,300 は図では 2,600・3,435（作業時）／3,155（走行時）。70t の piv_b 1,500・piv_h 2,800 は 3,000・3,748／3,451。hook_t は 25t 0.25→公表 0.22、50t 0.45→0.46、70t 0.6→35t フック 0.34（70t 吊りは 35t フック×2＋重荷重装置）。

## 3. アウトリガの任意張出（左右・前後で別々の張出）の扱い（メーカーの記述）

1. **張出幅は脚ごとに検出する**: 全機種「スライド・ジャッキ各個操作装置付」「アウトリガ張出幅検出装置」（S13 p1、S16 p1、S25 p1、S60 p1、S70 p1、S100 p1）。35t は「Outrigger extension width detector (individual detection)」（S35 p2）、GR-350N-1-00104 は「アウトリガ張出幅自動検出装置（個別検出式）」（S35b p3）。
2. **側方は張出幅の表、前方・後方は最大張出の表（範囲が角度で変わる）**: 「側方域でのつり上げ性能は、アウトリガ張出幅によって異なります。張出幅に応じた性能で作業をしてください。また、前方・後方域でのつり上げ性能は『アウトリガ最大張出』の定格総荷重ですが、アウトリガ張出幅によってその前方・後方域の範囲（角度a）が異なります」（S13 p4 注意 8、S16 p2 注意 7、S25 p2 注意 7、S35 p8 注意 8、S50 p11 注意 7）。角度 a は車体の前後軸から測る（図）。
   - 13t: 4.3m→45°、3.5m→35°、2.5m→25°、最小（1.7X/1.64H）→15°（S13 p4）
   - 16t X: 4.8→50、4.4→45、3.2→20、2.7→15。H: 4.8→45、4.4→40、3.2→20、1.79→5（S16 p2）
   - 25t X: 6.1→45、5.0→25、3.6→15、3.1→10。H: 6.1→45、5.0→25、3.6→15、2.3→5（S25 p2）
   - 35t: 6.3→50、5.2→40、3.8→25、3.3→20（「最小値」と注記）（S35 p8）
   - 50t: 6.8→45、5.5→35、4.1→25、3.5→20（S50 p11）

5. **ツールでの扱い（提案。資料の記述ではない）**: AML の補間と 5° の切換は資料に式が無いので再現できない。安全側にするなら「ブームを向ける側の 2 脚のうち小さい張出幅の表（表に無い幅は、その幅以下でいちばん大きい表）」、前後方域（角度 a の内）は最大張出の表を使えるが、角度 a は「左右の小さい方の張出幅」の値（60〜100t はフロント・リヤの組合せ表）で判定する。もっと簡単には「4 脚の最小の張出幅の表を全周に」（今の table_for と同じ考え）。

## 7. 読み取りの方法と注意

- 13t・25t・60t・70t・100t・50t: 文字のある PDF。pdftotext -bbox の語の位置で列（ブーム長さの見出しの x）に割り付け、頁の画像と突き合わせた（13t p2・p3、25t p4、60t p5、70t p13、100t p32、50t p6 を画像で確認）。
- 16t: 画像だけ。250dpi で表ごとに切り出して目で写した。全表で「半径が増えると定格が増えない」「張出幅が小さいと定格が大きくならない」を確かめた（全機種の辞書で同じ確認をして違反なし）。
- 35t（S35）: 日本語フォント（MS-Mincho）が埋め込まれておらず、画像にすると文字が右へずれて罫線と合わない（列を取り違える状態）。そのため**値の並び順**だけを使い、各行の値はブーム長さの連続した範囲として、全列がそろう行より上は左詰め・下は右詰めで割り付けた（表の起伏角の範囲 A とも合う）。また頁の右端からはみ出した値は、取り出し範囲を広げて（pdftotext -W 1400）読んだ（3.8m 表の 36.3m 列 6.5m＝7.0、8.0m＝6.7、9.0m＝5.5）。画像での列の確認はできていない。
- 60t・70t: 同じブーム長さで伸縮モード1・2の2列（100t は伸縮状態 ID ごとに最大4列）。辞書は大きい方（既存の 70t と同じ考え）。60t 7.6m・100t 7.8m は、データシートの「最大になる性能を抜粋」した表と全行一致したので、この取り方はメーカーの抜粋と同じ。実際の作業では伸縮モード（ID）を選ぶ必要がある（S60b p4、S100b p15）。モード別の生の値は research5/tadano_tables_raw.json に残した。
- 表の※（60t 10.3m の 1.8〜2.5m 等）は重荷重装置付の値。辞書では文字列 '※60.00' のまま残した。
- 中間の作り物の作業ファイル: research5/tools/（words.py・mb.py・seq.py・gen.py・dicts.py・final.py）、research5/tables_part1.json・tadano_tables_raw.json・dicts.txt・dict160.txt。画像は research5/tadano/img/。
