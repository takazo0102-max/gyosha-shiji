# ashiba — Archicad 仮設足場計画ツール（くさび緊結式）

Archicadの躯体モデルから、くさび緊結式足場の**割付・法規チェック・数量拾い・帳票生成**までを
一気通貫で行うツール。コアバリューは「Archicadから出ない。線を引けば割付が解けて、法規チェックまで付く」。

## 実装状況

指示書のPhase 1〜4をすべて実装済み。ユニットテスト1959本＋Archicad 28実機でのE2E検証を通過。

| できること | 実装 |
|---|---|
| 総合判定 | 法規・構造・付帯設備・数量をまとめて1つの判定に。是正項目と着手前チェックリスト（要確認一覧）を割付レポート末尾と設置届の2枚目に出す |
| 平面割付 | コーナー固定点＋真物DPスパン割＋離れ最適化＋全体XYシフト（出隅の回し・入隅対応） |
| 立面割付 | コマピッチDP／建枠積み上げ・ジャッキ端数吸収・千鳥（選べる） |
| 法規チェック | 12項目（安衛則の根拠条文付き）。是正が要るものは数量にも反映するか、含んでいないことを本数で明示する |
| 構造計算 | 風荷重・壁つなぎ（支配面積）・建地圧縮（局所荷重込み。日建NDは拡幅部・荷取り部・強力つなぎ材の許容値を区間に応じて使い分け）・荷受けステージの受けブラケット（本/スパン当たりの許容）・開口部の梁枠（梁枠上の積載制限・支点の軸力・両端支柱の反力） |（最も近い壁つなぎで面を分ける支配面積）
| 自動決定 | 壁つなぎ間隔（構造から逆算）・階段位置・朝顔段数・必要な詳細図 |
| 選べる | 手すり方式（先行手すり／布材＋幅木）・階段位置（自動／手動指定） |
| 敷地対応 | GL高低差 → 支柱ごとのジャッキ量一覧 |
| 足場方式 | くさび式（信和A/B・次世代・日建ND1800/ND1900）＋枠組式＋単管（クランプ）／本足場・ブラケット足場（支柱・単管）・単管抱き足場（床の枚数と受けブラケットまで反映） |
| 付帯設備 | ブラケット区間・荷受けステージ（張出ブラケット・方杖まで作図）・昇降機（マストと乗り込み口を平面・立面・3Dに作図）・開口部（梁枠）。同じ区間に重なる組合せは衝突検査で止め（階段室×昇降機・階段室×ステージも）、階段室の自動配置は開口部・ステージ・昇降機のスパンを避ける。開口部で抜いた支柱に当たる壁つなぎ（格子・取付部・マスト控え）は両端の支柱へ寄せる |
| 出力 | 数量表CSV・割付レポート・ジャッキ量一覧・設置届一式Excel（10シート＋開口部があれば計算書4）・plan.json（スキーマ明記・入力の区間指定まで往復） |
| 壊れ方 | 入力JSON・マスタCSV・Archicad接続の失敗は原因と直し方を日本語で返す（終了コード2）。一括配置は途中失敗で置いた分を消す |
| Archicad | 足場ラインGDL（1辺=1オブジェクト・平面/立面を切替）＋詳細図5枚の2Dシンボル。plan.json だけからの再配置も可。平面・立面・3Dは同じ入力から描き、床を敷かない区間（階段室・開口部）・抜いた支柱・階段・梁枠・敷地高低差（脚ごとの地盤高とジャッキ、継ぎ足した支柱）も一致する |

## アーキテクチャ

```
躯体外形（Tapir経由 or JSON） → 割付エンジン(純Python) → 足場ラインGDL配置 + 帳票出力
```

- **割付エンジンはArchicad非依存**（`src/ashiba/`）。Tapir接続は `tapir_adapter.py` に隔離
- **足場ライン方式**（最重要決定）: 部材1本ごとにオブジェクトを置かず、
  1つの辺＝1つのGDLオブジェクト（`gdl/hsf/ashiba_line/`）が内部で
  支柱・布材・踏板・手すり・幅木・ブレスをパラメトリック生成する
- 部材マスタは外部CSV（`data/part_master.csv`）。**系列ロック**でインチ/センチ混在を機械的にブロック。
  差し替え用CSVはExcel保存のBOM付きUTF-8・Shift_JISをそのまま読み、列不足・数値でない値は
  行番号と型番つきで指摘する
- 呼び寸法(nominal)と実寸法(actual)を厳密分離: 割付計算は呼び寸法、描画は実寸法

## 使い方

### スタンドアロン（Archicad不要）

```bash
cd ashiba
PYTHONPATH=src python3 -m ashiba.cli examples/rect_30x20.json --out out/
```

入力ファイルが無い・空・壊れている・文字コードが違う場合も、トレースバックではなく
原因と直し方を出して終了コード2で止まる（BOM付きUTF-8はそのまま読む）。
入力JSONは実行前に検証する。未知のキー（`loading_stages` を `loading_stage` と書く等）・
必須キーの欠落・型違い・`standoff` の大小関係の矛盾はまとめて指摘して終了コード2で止まる。
廃止したキー（`n_stairs` → `stairs.count`）は名指しで新しい書き方に誘導する。
黙って既定値に落とすと、指定したつもりの朝顔やステージが計画から消えても気づけないため。

## 構造計算と壁つなぎの自動最適化（Phase 2）

**構造計算書の扱い**（Phase 12-2）: 設置届一式の計算書（計算書1〜4）は**有資格者の確認前提の下書き**。各シートの冒頭に
その旨を書き、末尾に「確認（有資格者が記入。ツールは記入しない）」の欄（確認者 氏名・資格・確認日・所見）を置く。
計算に未確認の耐力値（`data/capacity.csv` の `verified=no`）を使ったときは、確認欄にその名前を挙げる。
運用: ツールは確認欄を埋めない。総合判定の「成立」は確認の代わりにならず、確認欄に署名が入るまでは提出図書ではない。
確認者が数値を直したときは、Excel の該当行を直すか、入力（`site` など）を直して出し直す。

指示書§6の式をそのまま実装している。

```
設計風速 V = V0 × K(高さ) × E(近接建物 1.0〜1.3) × S(地域区分)
速度圧   q = 0.6 × V²                                   [N/m²]
風力係数 C = (0.11 + 0.09γ + 0.945×Co×R) × F            （Co=1.57、メッシュ R=0.7）
壁つなぎ P = C × q × A ≦ 許容耐力 × 1.3                （A＝支配面積、格子なら lh×lw。風荷重時30%割増）
建地圧縮 N = 自重 + 積載 ≦ 許容支持力                     （ジャッキ繰出し長で変動・線形補間）
```

**壁つなぎは法規だけでなく構造計算から逆算して確定する。** 実装上いちばん効く差別化点で、
「垂直5m×水平5.5mの法規上限は満たすが風荷重では耐力不足」という実際に起こるケースを拾う。
`optimize_wall_ties()` が部材数の少ない配置から順に試し、法規と検定比≦1.0を同時に満たす
最も緩い配置を採用して、その本数が数量表・図面にそのまま反映される。
最密（1スパン×1層毎）でも足りないときは、最後に「角から1.8m未満の支柱にも入れる」配置を試す。端のスパンが短い面（インチの1524・610など）では角の手前の支柱が配置の決まりで外れ、朝顔の取付部の1本だけが端の領域を受けて NG になっていた（例: インチ30×20m・沖縄 → 角の手前にも入れて検定比1.14→0.82、432箇所）。
（例: 関東沿岸・メッシュ養生・H16.3m → 3スパン×2層毎ではNG →
 2スパン×1層毎に自動で詰めて検定比0.88でOK、壁つなぎ224箇所。
 壁つなぎの許容耐力は仮設工業会認定基準の4.41kN/本）

### 壁つなぎの支配面積（Phase 4）

検定に使う面積は「最大垂直間隔×最大水平間隔」ではなく、**壁つなぎ1本ごとの支配面積**を
求めて最大のもので検定する（`tie_tributaries()`）。境界の扱いは、そこが構造的な支点かで決まる:

| 境界 | 扱い | 理由 |
|---|---|---|
| 最下段の下側 | 半分 | 足場脚部（ジャッキ・根がらみ）は支点 |
| 最上段の上側 | 全長 | 自由端の張り出し |
| 面の端（コーナー） | 半分 | コーナー支柱は両面共有で直交面に支持される |

最大間隔の積で一律に評価すると、その2つが別々の壁つなぎで起きている場合は過大評価になり、
逆に最下段のように片側が長い壁つなぎは過小評価になる。支配面積なら**どの1本が支配的か**も
帳票に出せる（計算書2に「辺0 始点から7200mm 高さ4600mm」のように記載）。

受け持ち領域は面（足場長×高さ）を**最も近い壁つなぎ**で分けて求める（ボロノイ分割、上の境界規則つき）。
格子状の配置では従来の「隣との中間まで」の長方形と一致する。以前は同じ高さの列の中だけで隣を探して
いたため、荷受けステージ取付部のように格子と違う高さに1本だけある壁つなぎが右隣を面の端までと数え、
14.6m²の支配的な1本になって「壁つなぎを足したのに検定が悪化」していた。同じ理由で、壁つなぎの
最適化は朝顔・ステージ取付部の壁つなぎと開口部の寄せを載せた一覧で候補を検定する（最終検定と同じ一覧）。

⚠️ 境界の支点扱いは工学的仮定。提出図書に使う際は有資格者の確認を受けること。

  くさび専用の特記を枠組の図に書いてしまう

### 足場高さの直接指定と、面ごとのスパン指定

足場高さは既定で軒高＋手すり分（`eaves_height_mm` + `guard_extra_mm`）を目標に解く。
くさび式の本体は、1層目の作業床を 1.8m 前後（階高±半コマ。ND1800 は 1575〜2025、ND1900 は 1900 前後）にそろえる
（利用者の指定 2026-10-25）。床は最上層から階高ずつ割り付けるので、軒高によっては天端を最大で階高ぶん上げる（最上層の床が
軒より上に出る。帳票に注記）。足場高さを直接指定したとき（3D の天端のつまみ・地足場）と、床を本体にそろえる上段は指定のまま。
`scaffold_height_mm` を書くとその値を目標にし（軒高より低ければ警告）、割付の警告に「指定値で解いた」と残す。

その面はその構成で固定し、離れだけを解き直す。寸法は系列の布材にあるものだけ。合計が面の足場長から
大きく外れると入力エラーで止まる。

```json
"scaffold_height_mm": 15000,
"span_overrides": [
  {"face": "南面", "spans_mm": ["1800x5", 900, 900, "1800x11"]},
  {"edge_index": 2, "spans_mm": [1800, 1800, 1200, "1800x8"]}
]
```

### 出隅コーナー

内側建地列は隣の面とコーナー支柱を共有するが、外側建地列は面ごとに躯体コーナーで終わるので、
四隅の外側の升目（外側コーナー支柱・前後2辺の布材〈根がらみ・床・手すり・中桟〉・コーナー踏板・幅木）は
始点側の面が描く（各面が始点支柱を所有する規則と同じ向き）。数量も同じ規則で、外側コーナー支柱は
支柱位置数に足し、布材・幅木は腕木の呼び寸法で計上する。コーナーの床は、長さ＝建地列間隔の踏板（信和 600・日建 610）を本体の床と同じ幅の組み合わせで出隅×層の枚数だけ計上する（Phase 11-2。踏板のセル数とは別に「出隅コーナーの床は…」と注記）。マスタにその長さの踏板が無い幅と、一側足場（コーナーの升目がブラケットの床幅で決まる）は、今までどおり手配の注記に枚数を出す。
一側足場でも同じ（建地列が躯体コーナーで終わるのは同じ）。枠組には無い。

### 敷地メッシュ（敷地境界・足元の勾配）

利用者の指定（2026-10-24）「メッシュの敷地境界線としてと足元の勾配に合わせるように配置するような機能つけて」。

### 条件は Archicad の中で（足場条件の部品）

ツールバーを最初に実行すると、建物の左下（断面の切断線より外）に「足場条件」の札が置かれる。条件はその部品の設定ダイアログ（ページ: 基本／高さ・離れ／安全・表示／部材編集）で変えて、もう一度ツールバーを実行する。部品の値はデスクトップの JSON より優先し、条件はプロジェクトと一緒に保存される。系列を空にするとモジュール（メートル／インチ）の既定系列になる。開口部・荷受けステージ・昇降機・スパン指定など一覧で持つ条件は JSON（またはホットスポット編集と `read_back_spans.py`）のまま。パラメータと JSON の対応は `spec_object.FIELDS` が正で、GDL のパラメータ・設定画面と一致することをテストで確かめている。工事名を変えて再実行すると、同じ建物の古い名前の断面・レイアウトは片付ける（控えに建物と工事名を記録）。

PDF は当面、Archicad のパブリッシャーで「2 - レイアウト」のサブセット「仮設足場」を選んで発行する（Tapir の `PublishPublisherSet` は Archicad 30 で応答が返らず止まったため、ツールからは呼ばない）。

  足場の立つ面（地盤・下の屋根）と同じ高さのスラブ、足場より2m以上上のスラブは張り出しとみなさない。

  上の層は奥行きを足した離れで内ブラケットを選ぶ（踏板が足りなければ落下防止材の案内）。大きいセットバックは従来どおり、上のスラブを選んで
  もう一度実行すると下の屋根の上から建てる。

### 足元の高低差（外側の建地列）

敷地メッシュから、内側の建地列だけでなく外側の建地列の脚も、その位置の地盤で解く（同じ基準面・同じ規則でジャッキ・敷板・継ぎ足し支柱）。
斜面が面から外へ下がると、外側の列の脚は内側より長くなる。ジャッキ量一覧に「列」（内・外）を足し、数量（支柱・ジャッキ・敷板・継ぎ足し部の
根がらみ）は内外の脚をそれぞれ数える。足場ラインは外側の列を `glListO`・`jackListO`・`shimListO` で描き、立面図（外から見る）は外側の列の地盤で描く。
一側足場は建地が外側の1列だけなので、その列の地盤で解く。枠組は建枠1枚が内外の脚を兼ねるので段数は内側に揃え、差はジャッキで受ける。

### 区切る（パレットのメニュー「区切る」「区切りを戻す」）

足場ライン（面ごとに1部品）を垂直・水平に区切って、別々の部品にする。3D で足場ラインを選ぶと、上端（外側建地列の外）に
縦の区切りのつまみ、始点の支柱の外に横の区切りのつまみが出る。引いた位置の次の支柱の芯・次の作業床に吸着して赤い面が出る。
「区切る」を押すと、そこから先が別の部品（同じ足場ラインの写しで、範囲 `segSpanA〜segSpanB`・`segLevA〜segLevB` だけ違う）になる。
縦の区切りは支柱の芯、横の区切りは作業床の 100 下（床・腕木は上の部品、手すりは下の部品）。3D は部品の範囲の箱の外を切り取り、
平面・一覧表の図示本数は範囲の中だけ（付帯設備・壁つなぎは始まりが範囲にある部品、上の部品の平面は範囲を破線で囲む）。
「区切りを戻す」で同じ面の部品を1つに戻す。「配置」で置き直しても区切りの無い面に戻る。

### 支柱だけ分解（パレットのメニュー「支柱だけ分解」「分解を戻す」）

足場ライン（区切った部品でもよい）を選んで「支柱だけ分解」を押すと、支柱（コマ・継手付き。梁枠の上の支柱・出隅の外側コーナー支柱も。
枠組は建枠を1枚ずつ）を1本ずつの部品（`ashiba_member`）にする。1本ずつ選んで消す・動かす・コピーでき、Archicad の一覧表にも
1本ずつ出る。ジャッキ・布材・踏板・手すり・ブレース・階段・朝顔などは足場ラインのまま（`explodeMask` は支柱だけを描かない）。
区切った部品は自分の持つ支柱（位置が部品の始点〜終点の手前、下端が部品の高さの範囲）だけを分解する。
以前は布材・踏板なども全部分解していたが、建物1棟で約1400本になり重かったので支柱だけにした（2026-10-21 利用者の指定）。
「分解を戻す」で支柱を消して元に戻る。「配置」で置き直しても元に戻る（分解した支柱も消える）。

### 条件の登録と呼び出し

参考: smartCON Planner の足場条件の登録。会社・現場の定番の条件に名前を付けて控え、別の建物へ呼び出す。

### 部材編集（範囲を指定して外す・置き換える）

参考: smartCON Planner の「一般部材編集」。自動割付のあとの現場ごとの直しを、升目（面・スパン・層）の範囲で持つ。
足場条件の部品の4ページ目「部材編集」に1件ずつ `面 スパン 層 部材` を `;` で区切って書く（入力 JSON では `member_edits`）。

```
南面 2-3 2-3 踏板・幅木 #設備の搬入口;  東面 1 全部 手すり→NDT09S;  北面 全部 4 筋かい
```

- スパンは面の始点から 1, 2, …、層は作業床の 1層目（最下段）から。`3-5`・`全部` が使える。層を省くと全部の層
- 部材は 踏板・外側手すり（先行手すり）・幅木・筋かい・内側手すり。`→品番` で置換（数量だけ付け替え、図は変えない）
- 上の層だけ床を狭める（層ごとの幅の変更）ときは 外側踏板・内側踏板 の片側だけを外す（例 `南面 全部 5-6 内側踏板`）。支柱の位置は変えない
- 外すと数量表・層別・面別の数量から引き、3D と部品の図示本数でも描かない。平面には区間を破線で囲んで「外す 床幅 2-3層」と書く
- 手すり・幅木を外したら「墜落の危険」を要確認に出す。開口部の升目・足場の中の階段室の床は対象外（注記する）

### 立面図は断面図ビューポイント（立面ツール相当）でレイアウトへ

`elevation_mode`（既定 `"section"`）では、立面図を平面図の下に2Dオブジェクトで並べるのではなく、面ごとに **断面図ビューポイント** を作って3Dから投影し、レイアウトブックのサブセット「仮設足場」の下に面ごとのレイアウトを作って図面として置く。Tapir には立面図マーカーを作る命令が無いので断面図を使う（切断線を足場の外側建地列から3.5m外に置き、始点→終点の左手＝躯体側を見る。奥行きは躯体の最も遠い頂点まで。見え方は立面図と同じ）。縮尺は用紙（マスターレイアウトは A1 を優先）に収まるように 1/100 から選ぶ。3Dをそのまま映すので、支柱・布材・斜材・階段・付帯設備・天端のスパン寸法文字が平面と食い違わない。

断面立面には注記を入れる（`ChangeWindow` で各断面を開いて `CreateTexts`／`CreatePolylines`）: 天端の上にスパン寸法、右に各層の作業床高さ・根がらみ・GL、足場高さの寸法線、上に面の要約2行（系列・モジュール・作業層・階高／壁つなぎ本数・離れ・ジャッキ繰出し）。断面の横軸は「切断線の向きへの平面座標の射影」、縦軸は標高。断面を消すと中の注記も消えるので、再実行は断面の作り直しだけで置き換わる。3Dのスパン文字は断面・立面では潰れるので出さない。

全面が1枚の用紙（1/100〜1/200）に収まるときは1枚のレイアウト「<project_name> 足場立面図」に左上から並べ（30×20m・A1 なら 1/100 で2行）、収まらなければ面ごとのレイアウトにする。並べ方は、元の大きさで仮置きして図面の実寸（注記・フロアマーカーの張り出し込み）を測り、実寸で縮尺と位置を決めてから本配置する。縮尺は比率（`scale`）で付ける（`drawingScale` は縮尺名だけで大きさは変わらない）。図面の削除はレイアウトが前面のときだけ通る。断面の作成・削除は平面図のウィンドウが前面のときだけ通るので、ツールバーは処理の前後に `ChangeWindow` で平面図へ切り替える（レイアウトを作ると Archicad がそのタブを前面にし、そのまま再実行すると "Failed to create section" になっていた）。壁つなぎの記号は立面が ◎（平面は ▽）。◎ は3Dには持たせず、断面の立面図に注記（2重の円の折れ線、半径120・65mm）として描く。

**足場平面図**も同じサブセットにレイアウト「<project_name> 足場平面図」を作り、配置フロアの平面図を足場の範囲（躯体外形＋離れ＋建地列＋断面の切断線まで）で切り抜いて置く（A1 なら 30×20m は 1/100）。切り抜きの枠（`clipPolygon`）は用紙の絶対座標、中身は「用紙＝pos＋モデル×縮尺」で、Tapir は pos＝position−枠の最小角×比率（比率＝元の平面の縮尺/置く縮尺）にするので、position＝枠位置×(1+比率)−範囲の最小角×縮尺 で渡す（実機で確かめた関係。比率1なら 2×枠位置−…）。

**寸法とラベル**（参考: micotoworks「足場図面の書き方」）: 寸法は足場から離して置く（立面はスパン寸法を天端の1.2m上・全長をその上、高さの寸法線を外側建地の1.5m右。平面はスパン寸法の寸法線を外側建地から約0.9m外・全長をその外。朝顔などの張り出しがあればその外）。部材名は Archicad の文字ラベル（引出線つき）で、立面は断面の中に、平面は配置フロアに置く。平面のラベルは建物ごとに GUID を `ashiba_out/plan_labels.json` に控え、次の配置・撤去で消す。

**PDF 一式**（Phase 9-5）: 断面図方式のときは最後に、この工事の足場レイアウト（立面図・平面図・詳細図）だけを Archicad の発行セット（既定「2 - レイアウト」、入力 `pdf_publisher_set`）から PDF に発行し、`ashiba_out/PDF/<プロジェクト>/<サブセット>/` に出す（`pdf: false` で発行しない）。発行の項目は `{"navigatorItemId": {"guid": …}}` の形で渡す（`{"guid": …}` だけだと「corrupt or missing」）。3枚で約30秒。以前の「20分以上止まる」は、Archicad を長時間使い続けて図面の生成が詰まっていたときで、再起動後は通った。

**足場詳細図**（Phase 9-3）もレイアウト「<project_name> 足場詳細図」に置く。詳細図の部品は平面の建物の下に一列に置き、`detScale`（詳細図の縮尺の分母）を渡してその縮尺で読める文字の大きさで描かせる。実際の外形（`API.Get2DBoundingBoxes`）を測って重ならないよう詰め直し（`MoveElements`）、詳細図ごとに切り抜いた図面を 1/20 で並べる（入らなければ 1/30・1/50。昇降機の詳細図は高いので 1/50 になる）。以前は 1/100 の文字のまま 4m おきに置いていたため、詳細図どうしが平面で重なっていた。図面名は「脚部詳細（…）S=1/20」のように縮尺付き。

**表題欄**（Phase 9-4）: マスターレイアウトの表題欄はプロジェクト情報のオートテキストを映すので、工事名（`notification.site_name`、無ければ `project_name`）→プロジェクト名、`site_address`→敷地 住所、`contractor`→連絡先 会社、`planner_name`→連絡先 氏名 をプロジェクト情報へ入れる（[project_info.py](src/ashiba/project_info.py)）。プロジェクト情報は建物本体の図面と共通なので、**空の項目と、前回ツールが書いた値のままの項目だけ**変え（書いた値は `ashiba_out/project_info.json` に控える）、利用者が入れた値は残して案内を出す。マスターレイアウトは API で開けない（`ChangeWindow` が失敗）ので表題欄そのものには触らない。

Archicad が操作中（ドラッグ・ダイアログ・再構築）だとアドオンの命令が待たされる。ツールバーは最初に応答を待ち（最大2分）、読むだけの命令は時間切れなら再試行する。作る・消す命令は Archicad 側で実行済みのことがあるので再試行しない。断面は作った直後に控えを書く（時間切れで止まっても次回消せる）。撤去 `--all` は、控えに無い残骸の断面も、プロジェクトの断面がすべて足場の立面なら消す。

再実行は同じ名前のレイアウトを消し、断面は配置時に控えた要素 GUID（`ashiba_out/elevation_sections.json`）で消して置き換える（断面のナビゲータ項目は API で消せない。サブセットも消せないので「仮設足場」は再利用）。撤去スクリプトも同じ控えで消す。`"object"` にすると従来どおり平面の下に2Dオブジェクトで並べ、`"none"` なら作らない。

足場ラインは面ごとの**図示本数**をパラメータに書き戻す（`qtyPostPos` 支柱位置・`qtyPost` 支柱・`qtyNuno` 面に沿う布材・`qtyDeck` 踏板セル・`qtyToe` 幅木・`qtyAdv` 先行手すり・`qtyTie` 壁つなぎ・`qtyBrace` 斜材・`qtyStair` 階段）。Archicad の一覧表（スケジュール）で面ごと・建物ごとに集計できる。発注数量の正は数量表で、図示本数は照合用（腕木・出隅コーナーの部材・ステージやブラケット区間・高低差の継ぎ足しは含まない）。同じ式を `face_drawn_counts()` に置き、4面の合計が数量表と一致することをテストと実機の読み戻しで確認している（30×20m・8層: 支柱600・壁つなぎ250・斜材40・階段16・踏板432セル×2枚・幅木464＋コーナー64・布材2900＋腕木522＋コーナー200）。

平面には躯体面と内側建地列の間の離れ寸法を面の両端のスパン中央に入れる（寸法線は面に直交、値は線の脇。端数スパンや渡しで途中の離れが違っても両端で分かる）。

表示の切替はモデル表示オプション（部品 `ashiba_mvo`、「仮設足場の表示設定」）でもできる: 平面の詳細／単線（建地列・支柱位置・床の対角線・階段の矢印・付帯設備の占有範囲だけ）、寸法・注記の有無、3Dの立体／線表示。MVOがあれば部品の `planSimple`・`showDim`・`lineMode` より優先する。

平面では支柱位置のホットスポット（建地列の中央）を引いてスパン境界を動かせる（`editSpan`、始点・終点は固定）。部品の1Dスクリプトが規格寸法（`sizeList`＝系列の布材）だけで面の長さを保つように吸着して `spanList` を書き戻す: 引いた境界の手前を規格寸法に、残りが規格ならそのまま（1800+900 → 1500+1200）、違えば規格2本に分けて1本挿入（1800+1800 を 1500 に引くと 1500+1500+600）、隣の境界まで引くと結合（900+900 → 1800。合計が規格に無い 1800+900 は結合しない）。どれもできなければ動かない。同じ規則を `span_readback.snap_boundary()` に置いてテストしている。動かした割付は `scripts/read_back_spans.py` で読み戻し（足場ラインは配置時の plan.json の位置で見つけるので、スラブの選択は要らない）、`--write` で `ashiba_spec.json` の `span_overrides` に落とす。`--apply` なら続けてツールバーを実行して解き直す（部品を動かしただけでは帳票は追従しない）。

**階段室の位置**（Phase 10-2）も平面で引ける。階段室ごとに建地列の中央（内外の列の間）にホットスポットがあり、引くと部品のパラメータスクリプトがいちばん近いスパン境界へ吸着し、同じスパン数で長さを取り直して `stairList` を書き戻す。`read_back_spans.py` は動いた階段室があれば全階段室を `stairs.positions` に書く（位置指定にすると自動配置をやめるため、動かしていない階段室も今の位置で書く）。`--apply` で解き直すと数量・法規（昇降設備までの水平移動30m）が追従する。部品は配置時に `stairList` と開始位置の配列 `stEdit` をそろえて受け取り、両者が食い違えば「引かれた」とみなす（API で値を変えたときは `GLOB_MODPAR_NAME` が変わったパラメータ名にならないので、名前では判断しない）。荷受けステージ（張り出し床の中央）と昇降機（搬器の中央）も同じ仕組みで引ける。ステージはスパン境界に吸着し、複数の層に置いたステージは層ごとの組をまとめて動かす。昇降機は支柱位置に吸着せず50mm単位に丸め、乗り込み口（`landingList`）も一緒に動かす。読み戻すと入力の `loading_stages[].start_mm`・`hoists[].position_mm` を書き換える（辺は `edge_index` か `face` で照合）。

3Dの天端の外側に各スパンの呼び寸法を文字で立てる（`showDim` に従う。平面を開かずに割付を読める）。

3Dの緊結部まわりは実寸で描く（次世代足場.gsm で確認した寸法）: コマ（フランジ）φ106 t6、布材は支柱芯から78内側で管が終わり爪でフランジに掛かる、踏板は支柱芯から70逃げる、ジャッキベースはナット・ロッド・140角の板・ハンドル。支柱に貫入させて描くと緊結部の納まりが見えない。

3Dは `line_mode_3d`（既定 false）を true にすると、部材の立体を描かず支柱・水平材・階段・付帯設備の占有範囲を線だけで描く（部品の `lineMode`。計画初期や40m級の建物一周で軽い。bim-arekore の足場計画.gsm の「線表示」と同じ考え方。干渉確認は立体表現で）。

**3Dの細かさ**（部品の `detail3d`、またはモデル表示オプションの「3Dの表現」）: 自動（既定）・精細・軽量・線・ブロック。軽量は布材の爪・支柱の継手のカラー・ジャッキのハンドルを省き、円柱を6角にする（部材の位置・本数・寸法は精細と同じ）。コマ（緊結部の座）はカタログの支柱図どおり支柱1本ごとに描く（ND1800・ストロング: 上端から55下を起点に450ピッチ、2700 などのベース用は下端から170に根がらみ用のコマ。ミレニューム: 上端から30・根がらみ用120）。根がらみ・作業床・手すりの高さもこのコマに合わせて解く。軽量ではフックを掛ける高さのコマだけ描く。支柱の継ぎ目は継手の帯（中央に溝）で全表示に描く。自動はスパン×層が40を超える面を軽量にする（30m面×8層なら軽量）。足場が重くて操作しづらいときは、モデル表示オプションで「立体（軽量）」か「線表示」にする。ブロック（参考: smartCON Planner）は部材を描かず、スパン×層の半透明の箱で足場の占める空間を出す（開口部の升目は空け、外付けの階段室は3列目の箱。いちばん軽い）。躯体・庇・隣地との取り合いを見るときに使う。パレットの「3D表示」は 自動→軽量→線→ブロック→精細 の順に切り替える。

**色**: 配置のたびにプロジェクトの表面材を名前で探し、足場（支柱・布材・手すり・階段）＝アルミ、踏板＝亜鉛、幅木＝黄を部品に入れる（`matScaf`・`matDeck`・`matToe`。見つからない部材は足場と同じ）。部品の設定で変えてもよい（次の配置で上書きされる）。

**壁つなぎ・水平ネット・ネットブラケットは別の部品**（`gdl/ashiba_tie.gsm`・`ashiba_net.gsm`・`ashiba_netbk.gsm`）: ツールバーが壁つなぎの位置ごとに `ashiba_tie`（クランプ＋本体＋アンカープレート、平面は ▽）、足場条件の「水平ネットの層」（入力 `horizontal_net_levels`、例 `[2, 5]`）に面ごとの `ashiba_net`（躯体と足場の隙間、床の50下）と内側建地ごとの `ashiba_netbk` を置く。部品は原点＝内側建地、`faceAng` で面の向き、`zH` で高さを持つので、数百本でもまとめて1回で置ける。壁つなぎを部品で置けたら足場ラインの `tieObj` を入れてライン側の壁つなぎを描かない。数量はネットの面積とブラケットの個数（マスタに無い系列は要確認の手配に出す）。置き換え・撤去・スモークの片付けでも一緒に消す。躯体の出隅の角に立つ建地のネットブラケットは、躯体の角へ斜めに向けて2面のネットの角を受ける（腕は角までの距離で伸ばす。利用者の指定 2026-10-24）。

**くさびの隅の隙間（コーナーステップ）は 150〜400mm**: 隙間の両側に建地が立つので、コマ（φ106）どうしが当たらずくさびを打つ手が入る 150mm を下限にする（80・109mm の隙間でコマが重なっていた。利用者の指摘 2026-10-24）。隙間の手前で前の面が止まる出隅は、外側の升目の前の面の側にも建地1本と布材（根がらみ＋各層の床）を立てて、升目を4本の建地で独り立ちさせる（`cornerSP`。布材・手すりの緊結部が宙に浮いていた）。数量の支柱位置・ジャッキにも足す。

躯体側（内側建地列）の手すり＋中桟は `inner_guard_rail`（既定 true）で布材として層・スパン毎に2本計上し、3Dにも描く（外側が先行手すりでも内側は布材）。一側足場・枠組には内側列が無いので付かない。false にすると計上せず、離れ300mm超の面には「躯体側手すり材は数量に含んでいない」注記が出る。

幅木は `has_toe_board` で独立に制御するので、どちらの方式でも付けられる。
法規チェック#3は先行手摺を「斜材が中桟を兼ねる」ものとして扱う。
（例: 30m×20m・H16.3m → 布材3422本 vs 先行手すり時 布材2494本＋先行手摺464本。いずれも腕木・躯体側の手すり込み）

### 階段（昇降設備）の位置指定と昇り方

位置を指定しなければ自動配置、指定すればその位置に置く。どちらも同じ検証を通すので、
指定位置が実務指針（水平移動30m以内）を外れていれば警告が出る。

```json
"stairs": {"positions": [
  {"edge_index": 0, "start_mm": 9000, "reason": "現場出入口の近く"},
  {"edge_index": 2, "start_mm": 14400}
]}
```

面は辺番号の代わりに**面名で指定できる**（`"face": "北面"`。`"北"` も可。同じ方位の面が複数ある建物では割付レポートの表記どおり `"南面(辺4)"` と辺番号つきで書く。`face` と `edge_index` の両方を書いて食い違えば入力エラー）。面名は方位（真北＝Y+）で決まり外形の整理の影響を受けないので、斜辺や凹みのある建物ではこちらを推奨する。

**辺番号（`edge_index`）は正規化後の外形の頂点順**（頂点0→1が辺0）。入力が時計回りなら反時計回りに直し、重複・共線の頂点や最小スパン未満の凹み・張り出し（渡す）は取り除くので、そのとき辺番号は入力の頂点順とずれる。整理した内容は警告に出し、割付レポートの平面割付表に辺・面名・躯体頂点（始点）を出すので、付帯設備の `edge_index` はそれで突き合わせる。

指定位置は**スパン境界に丸める**（階段室は支柱間に納まる必要がある）。
丸めたときは元の指定値と併せて警告に出すので、黙ってずれない。

**昇り方**は同じ向きで2層ずつ（2スパンの階段室で、奇数層へは始点側・偶数層へは終点側のスパンに1スパン分の階段）。
2層ごとに階段室を出て外の作業床を回るので、作業床が踊り場を兼ねる（踊り場の床材は使わない）。
階段室の床は各層で階段が上がってくる1スパンだけ開口にし、もう一方のスパンには敷く。
階段手摺は階段1つに両側の2本、階段開口部手摺と開口部幅木は出入口（＝各層の階段の上がり口）1か所に1組で計上する
（マスタに無い系列は要確認一覧の「手配」に本数つきで出す）。

### 階段（昇降設備）の自動配置

安衛則526条（高さ1.5m超は昇降設備）と実務指針（水平移動距離30m以内）に基づき、
足場中心線ループ上に均等配置する。コーナーから1スパン以上離し、階段室が占有する区間には
**踏板を敷かない（数量から差し引く）** ——支柱の二重計上と同じ性質の誤りを防ぐため。

最大移動距離は理想配置の式ではなく**実配置から計算する**。スロットへの丸めやコーナー回避で
位置がずれるので、式で出すと安全側の判断を誤る。
（例: 30m×20m・周長102.6m → 2箇所で最大28.8m。1箇所指定なら51.3mとなり警告）

### 系列（A / B / 次世代足場）

**踏板幅は系列で実寸が違う**（A:400/250、B:405/240）。既定値を決め打ちにすると、
系列を切り替えたときにマスタ引き当てが静かに失敗して数量が抜ける。
そのため `deck_widths` は未指定なら系列から引く（`SERIES_CONST`）。
明示指定した場合はそちらが優先される。

**次世代足場は専用系列を作らない。** 仕様3.1どおり「くさび派生（踏板幅500・階高1800/1900）」
として扱い、入力JSONの `"next_gen": true` で踏板幅だけ500に切り替える。
コマピッチ・階高は元の系列のまま。

### ブラケット区間

⚠️ **データ構造は「支柱ラインの変更」ではなく「面の区間属性」**（仕様4.3）。
支柱ラインは真っ直ぐ通したまま、`区間[12.6m-18.0m]は内ブラケットW400` のように面へ属性を付ける。
支柱位置を動かす実装にすると割付が壊れ、数量も二重計上になる。
テストで「ブラケットを足しても支柱位置が変わらない」ことを担保している。

調整手段の優先順位は **①スパン → ②離れ → ③ブラケット**。ブラケットは最後の手段。

検証ルール（[brackets.py](src/ashiba/brackets.py)）:
- 逆向き取付禁止（同一区間・同一層で内と張出が相反しない）
- 拡幅は下層建地間隔が上層の60%以上、かつ全層で1回まで
- 緊結部付ブラケットでの拡幅は方杖が必須

**離れ350超の自動の内ブラケット**（`auto_inner_bracket`、既定 true。足場条件部品の「離れ350超に内ブラケットを自動で付ける」）:
離れが目標上限を超える面に、系列の内ブラケットを全層・全長に付け、躯体側へ踏板を1枚敷く。
踏板は「躯体までの隙間（離れ−踏板幅−25）が50〜300mm」になる最小の幅を、品番の注記（踏板240用など）から選ぶ。
ブラケットと踏板は数量に入り（内訳「内ブラケットの踏板」）、平面・3Dの床は踏板の幅だけ躯体側へ出る。
措置した面の「落下防止材を検討」の注意と「躯体側手すり材は数量外」の注記は消え、付けた旨と隙間を出す。
入力に内ブラケットがある面は触らず、張出ブラケットの範囲は避けて残りに付ける（その面の注意は残す）。
枠組・一側足場は対象外。インチ30×20m（離れ364/394）は ND の NDBK03C＋踏板240 で隙間100/129mm。

### 荷受けステージ・昇降機

どちらも足場に取り付く付帯設備で、共通するのは**局所的に大きな荷重・反力が入る**こと。
全体平均の建地圧縮検定だけでは、ステージ直下の建地が抜ける。

荷受けステージは、直下の建地（間口のスパン数+1本）に張出しの偏心を割増して軸力を配分し、
**その最も厳しい1本で建地検定を行う**。耐力不足のときは一般的な対処ではなく
「積載荷重の低減、間口の拡大、支柱2本組」という荷受けステージ固有の対処を出す。
検証は手すり・幅木・方杖・最大積載荷重の表示（安衛則655条）を必須としている。
（例: 間口2スパン・出1500mm・積載9.8kN → 建地1本あたり+4.9kN、検定比0.76→1.47。くさび支柱の一般値6.86kNでは是正になり、メーカー認定値への差し替えか支柱補強を促す）

昇降機はマスト控えの壁つなぎを増設分として計上する。
**昇降機本体の基礎・構造は本ツールの対象外**で、その旨を必ず警告に出す（メーカーの計算による）。

⚠️ 張出しの偏心による割増係数（既定1.5）は工学的仮定。有資格者の確認を受けること。

### 朝顔（法規チェック#10）

高さ10m以上で1段・20m以上で2段が自動で入る（入力で明示指定も可、`"asagao": false` で無効化）。
突出2m以上・傾斜20度以上・取付部2スパン毎の壁つなぎをチェックし、数量にも反映する。

信和のセーフウイング（簡易落下物防止機材・張出1,280mm・25°、資料 swg.pdf）は
`"asagao": {"kind": "セーフウイング", "stages": 1}` で指定する。支柱ごとに1本＋張出部に幅400の踏板3枚/スパンを
数量に出す（キャッチャーB用も踏板はA系列のSD-4018を使う指示なので、B系列では手配項目に出る）。
防護棚ではないので、高さ10m以上の足場では法規#10が「朝顔が別途必要」のNGになり、届の下書きも「朝顔なし」と書く。
図面・3Dには指定どおり張出1,280mm・25°で描く。

昇降機のマスト・搬器が通るスパンは朝顔を切り欠く。衝突検査が該当スパンを指示し、平面・立面・3Dも
その区間を抜いて描く（`asaCutList`「開始,終了」。支柱の真上に立つ昇降機は両隣のスパン）。
3Dの昇降機は詳細図と同じ取合いで描く: 外側建地から隙間100mmを空けた搬器（`cage_width_mm`×`cage_depth_mm`、
手すり枠高さ2.2m、最下の乗り込み口の高さに置く）、その外側に0.30角のラック付きマスト（0.5mごとの横材、到達高さ＋1m）、
乗り込み口ごとの渡し板、`tie_every_mm` ごとのマスト控え（`hoistList` の5値目）。平面はマストの角を、立面はマスト・搬器（最下の乗り込み口の高さ）・控えの印を実線で出す。
数量は切り欠き前の全スパンで計上し、その旨を注記する。

## 敷地高低差と支柱ごとのジャッキ量（Phase 4）

仕様が「本ツール最大の差別化」と位置づける機能。敷地メッシュから各支柱位置のGL標高を取り、
**支柱1本ごとのジャッキ繰出し量を一覧で出す**（`ジャッキ量一覧.csv` と設置届Excelのシート）。

### 原理と不変条件

**布材・作業床レベルは全周で通す。** くさび式はコマ位置が支柱下端から固定ピッチなので、
作業床を揃えるには各支柱の下端が基準からコマピッチの整数倍だけ下がっている必要がある。
つまり支柱ごとに解くのは「何コマ下げるか」で、残差がジャッキ量になる。

```
支柱下端 + 下げ段数 × 刻み（くさび=コマピッチ／枠組=調整枠の高さ）＝ 基準面（全支柱で一致）
```

この不変条件は平坦・緩斜面・急斜面・段差・起伏、A/B系列・枠組のすべてでテストしている。
ジャッキで届かない分の地盤調整量は必ず `目標下端 − 実ジャッキ量` として求める
（符号を逆にすると下端がずれて作業床が通らなくなる。実装時に踏んだ）。

### ジャッキ可動域の物理的な制約

ジャッキの実用可動域（30〜270mm＝240mm）は**コマピッチ450mmより狭い**。
そのため高低差が1コマを超える敷地では、一定数の支柱がどうしても実務上限を超える。
基準面を全体シフトして超過本数を最小化したうえで（平面の「全体XYシフト」の垂直版）、
残りは黙って丸めず具体的な対処を出す:

- 高低差がコマピッチ以内 → 「床均しで高低差を N mm 縮めれば全支柱が上限内」
- 1コマを超える → 該当支柱ごとに「敷板で N mm 持ち上げ」「床掘りで N mm 下げ」を一覧に明示

（例: 高低差1236mmの斜面 → 脚部構成4種類・ジャッキ34〜435mm・上限超過16本を個別に提示）

Archicadからは `read_ground_model()` が敷地メッシュの頂点とレベリングサブラインを
標高サンプルとして読む。⚠️ 三角形分割による厳密な内挿ではなく近傍点の逆距離加重（近似）。

脚部・壁つなぎ・コーナーは常に、朝顔は高さ10m以上（20m以上で2段）、
梁枠は開口部がある場合のみ。判定理由は設置届Excelの添付図書シートに出力される。
図に描く値は計画値を使う（朝顔の突出・傾斜は指定値、脚部のジャッキ繰出しは
敷地高低差を解いた後の最大値、壁つなぎと離れの上限・目標帯はその計画の値）。
既定値で描くと、添付図書が計画と食い違う。コーナー部詳細は方式で納まりの説明が
変わる（くさび=支柱共有／枠組=隙間70mm以上とステップ）。梁枠の規格寸法も系列ごと
（A:3600/5400、B:3800、枠組:3658）で、梁枠上に乗る支柱の位置は割付の実測値を渡す。

### GDLの実装上の注意（実機で踏んだもの）

- **`detailType` はASCIIキー必須。** 日本語文字列をパラメータ値として外部からGDLへ渡すと
  比較が一致せず、全種が既定の図（脚部）になる。表示名だけ日本語にしている
- **未知キーは黙って別の図を描かず、図面上にエラーを表示する。** 上のバグを隠したのが
  「不明なら脚部にフォールバック」だったため
- **警告の赤ペン番号はペンテーブル依存**（検証環境ではpen6=青、pen20=純赤）。
  `find_red_pen()` が実際の色から赤を探して渡す／変数名は組込み関数と衝突させない（`acS` は ACS() と衝突し、部品のパラメータ設定が全部失敗する。`stW` は STW()（文字列幅）と衝突し、3Dが丸ごと描かれなくなった。GDLは大文字小文字を区別しない）
- **文字列連結の行継続には `\` が要る。** `+` で改行するとコンパイルエラーになり2Dが空白になる

### ⚠️ 耐力値の取り扱い

耐力値は `data/capacity.csv` に外出しし、各行が `verified` 列と `source` 列を持つ。
`verified=no` の値が計算に使われると必ず警告が出て、Excelの該当セルにも「※未確認値」と
印字される。安全に関わる数値を黙って使わないための仕組み。

警告・Excel注記・結果JSON（`structural.unverified_capacity_rows`）は、
**差し替える行を `series_id,item,key` で名指しする**。実際に検定を支配した行だけが挙がるので、
ジャッキのように繰出し量で行が変わる項目でも、どの1〜2行を直せば警告が消えるかが分かる
（補間値なら補間元の2行とも挙がる。片方だけ直しても未確認は消えない）。

| 項目 | 状態 | 根拠（詳細と出典URLは `data/CAPACITY_SOURCES.md`） |
|---|---|---|
| 壁つなぎ許容耐力 | **確定** | 仮設工業会認定基準 4.41kN/本（引張・圧縮とも）。認定試験の強度9.81kNは許容値ではない |
| 作業床許容積載荷重 | **確定** | くさび: 信和総合カタログ2025.06 p46 技術基準 250kg/スパン（同時2層）／枠組: 建枠幅で 500・370・250kg |
| 開口部（梁枠）上方の全積載荷重 | **確定** | くさび: 同カタログ 800kg以下／枠組: 認定梁枠 2スパン用7.85kN |
| 建枠（枠組）の許容圧縮耐力・ジャッキ | **確定** | 『足場・型枠支保工設計指針』繰出し長別 42.6〜37.2kN/枠の1/2（簡易枠は幅付きの行） |
| くさびの支柱／ジャッキ許容支持力 | 暫定 | 信和のカタログに記載なし。単管建地の一般値6.86kN（繰出し長で低減）。メーカー認定値に要差替え |

警告文には**実際に未確認の項目だけ**を挙げる（確定済みの項目を並べると、
どれを差し替えるべきか分からなくなる）。

## 割付エンジンの要点（開発指示書 §4 準拠）

- **平面**: コーナー頂点は固定点（端数を受けない）。各辺は両端固定で
  真物 {1800,1500,1200,900,600} のみのDPスパン割（切断調整は存在しない）。
  端数は壁離れ250〜350で吸収し、全体XYシフトで対面バランスを最適化。
  目標帯[250,350]を外れた面には**必ず**対処案が付く（350超は落下防止材／内ブラケット、
  顧客最小値（既定250＝目標下限。200まで許すなら `standoff.hard_min` を下げる）未満の離れは採らず、それでも組めなければスパン構成の見直し）
- **短い辺**（凹み・小さな張り出し・玄関ポーチ）も正しく割り付ける。
  スパン候補の探索下限は最小スパンであって最大スパンではない
  ——最大スパンで切ると短辺で1800×1本しか候補が出ず、成立する構成を黙って捨ててしまう。
  「大きいスパンを優先」は評価側（`_small_span_count`）で満たす。
  物理的に足場面を作れないほど狭い凹みは、理由と対処（直線で渡す）を添えて拒否する
- **斜めの辺**は、進行方向の外側にあるコーナーを経由する直交2辺に置き換えて割り付ける（`geometry.orthogonalize_diagonals`）。
  置き換えた2面は躯体との離れがコーナー側でそれぞれ最大 |q−c|・|p−c| 増える（斜辺に沿って線形）。
  「渡した区間」種別「斜辺」（`deep_end` で深い側）として持ち、平面図に実躯体線を斜めの破線で描き、
  措置の本数（内ブラケット／躯体側手すり）を要確認に出す。片方の成分が20mm以下の斜めは座標誤差として直交に丸める。
  区間の中の壁つなぎは位置ごとの離れで長さを選び、最長の壁つなぎでも届かない帯（面の端に接する区間はコーナー支柱まで）は
  壁つなぎを届く支柱へ寄せ、帯の風荷重は壁つなぎの検定から除いて「単管等の控え」を構造の要確認に出す（法規#7は帯を除いて判定、WARNで前提を明記）。
- **出隅は回し**（コーナー支柱1本を両面共有）、**入隅**は符号反転で処理。
  支柱帰属は「各辺は始点支柱を所有し終点支柱は所有しない」→ 二重計上ゼロ
- **立面**: 固定点は最上層作業床（軒高＋手すり分）、端数吸収は最下部（ジャッキ≤270＋短支柱）。
  コマピッチ刻みDPで、優先は 要求高さとの偏差 → 本数 → 繰出しの小さい方（繰出しは低く抑える。2026-10-25 の調査）。
  1段目は 2700（ND1900 は 2850）、その上は 3600 を積む（日建 ND1800 の要領書と同じ）。いちばん上の支柱は最上層の床より
  下から手すりの上まで1本で通す（継ぎ目を最上層の床より下に。天端に 450 を継ぐと継ぎ目が床＋505〈中桟と手すりの間〉に来て、
  手すりを短い支柱で受けることになる。利用者の指摘 2026-10-25: 最上部が450となってるが施工できるの職人目線で考えてみて）。
  例: 10.6m は 2700+3600+2700+1350（前は 2700+3600+3600+450）。途中に 450 を挟む並びは同じ高さで避けられれば避ける。
  継ぎ目は全部の支柱でそろえる（メーカーの要領書は全支柱同じ積み方で、千鳥の決まりは法令・技術基準・メーカーの資料に
  見当たらない。2026-10-25 の調査）。`"post_stagger": true` で1本おきの支柱の1段目を 900（ND1900 は 950）にして継ぎ目を
  1層ずらす（3D・数量とも。いちばん短い支柱の位置を動かして本体の継ぎ目と重ならない並びにする）。単管の建地は従来どおり千鳥

支柱の本数は足場ラインの 3D と同じ数え方: 面ごとに両端を含む支柱の位置 × 内外の列から、隅で共有する内側建地と
セットバックの上段の端を除き、出隅の外側の角の支柱を足す（前は「始点＋中間（終点は次の面）」× 列で、各面の外側の列の
終点の支柱〈隅の升目の4本目〉と隣の面の無い端の支柱が抜けていた。利用者の指摘 2026-10-25: 支柱の本数の数え漏れも直して）。
ジャッキ・アンダーベース・層別数量・構造計算の立っている本数・足場ラインの図示本数（qtyPostPos）も同じ数。セットバックの
下段の本体側の端は本体の支柱（全高）と同じ位置なので、下段は描かず数えない。

## 数量拾いの前提ルール（`QuantityRules` で調整可能）

- 本足場＝内外2列建地、支柱構成は内外同一とみなす
- 布材: 根がらみ内外2本＋作業層ごとに床レベル内外2本＋外側手すり・中桟2本
- 腕木＝内外建地列の間隔（`post_row_spacing_mm`。くさびは発注する布材、枠組は建枠幅）を
  支柱位置×(作業層＋根がらみ)。作業床の被覆幅とは別物なので混同しない
- **斜材（ブレス）は設置間隔から算出**: くさび式足場用斜材は6層6スパン以下毎に交さ2方向。
  全スパン×全層で拾うと1桁多く発注してしまう（30m×20m・H16.3mで40本 vs 896本）。
  会社の標準が全構面なら `QuantityRules(brace_every_spans=1, brace_every_levels=1)`。
  **どの間隔で拾ったかは必ず数量表の注記に残す**（発注数量が大きく変わるため）
- 枠組の交差筋交は全スパン×全段×**2本**（外構面・内構面の両方）。建枠と一体で構面を成すので
  くさび式の斜材とは考え方が違う。片面のみの現場は `frame_braces_per_bay=1`
- 枠組の布材は根がらみ2本＋最上層の手すり・中桟2本（中間層の手すりは1つ上の建枠が兼ねる）
- 荷受けステージ・開口部の梁枠も数量に計上する。カタログに無い寸法は代用せず注記に出す
- 離れが300mmを超える面は躯体側の手すり材を**含まない**（対処法が現場判断のため）。
  含んでいないことと該当スパン数を注記に出す
- アンダーベース数＝ジャッキ数＝支柱位置×列数（枠組は建枠1枚が2脚なので×2）
- 架け面積＝(建物外周+4m)×(建物高さ+0.5m)
- **床が無い区間は差し引く**: 階段室は全層、開口部は梁枠より下の層（通路）。
  幅木も床に付くので同じ扱い（階段室の外構面の幅木は残す）
- 一側足場は建地1列・床は1枚敷き。本足場の内外2枚敷きで数えない。
  片持ちになるので床受けブラケットを支柱位置×層数で計上する
- 張出しブラケット・荷受けステージは**開放端になる縁**の手すり・中桟・幅木を計上する
  （張出しは外縁、ステージは先端と妻側の左右）
- 高さ31m超は最高部から31mを超える部分の建地が2本組になるが、除外規定があるので
  自動計上はしない。対象区間と該当本数を要手配項目に出す
- 朝顔は落下物を受ける設備なので、隙間が残る箇所（出隅・端数スパン）を注記に出す
- 手配が要るもの（マスタに無い部材）と現場で対応するもの（塞ぐ・検討する）は
  要確認一覧で分類を分ける

  非直交は明示的に拒否。`nikken_nd1800` 系列はカタログ実品番・確定耐力値、
  `shinwa_A`/`shinwa_B` の支柱・ジャッキ耐力は暫定値（要確認項目が出る）
- 外形の重複頂点・共線頂点は取り除いてから割り付ける（除去内容は警告に出す）。最小スパン未満の凹み（幅か奥行）・張り出し（出）は足場を回り込ませず直線で渡し、増える離れを警告に出す（深い張り出しは回り込む）
- 部材の単位重量は、信和A/Bは総合カタログ2025.06、日建ND1800/ND1900・枠組は仮設資材カタログVol.10の
  実値。**型番仮の行（信和の朝顔）だけ概算**で、含む計画は要確認一覧に
  品番を名指しで出す。数量（本数）は割付から厳密、トラック台数は積載効率込みの概算
- Tapir接続・GDL 3D/2D生成は Archicad 28 (Mac, Intel) + Tapir 1.5.8、
  断面図方式の立面・平面図レイアウトは Archicad 30 + Tapir 1.7.0 で実機検証済み。
  ツールバーは起動時に版を読み、Tapir が 1.7.0 より古ければ立面を部品方式（`elevation_mode=object`）に
  自動で戻す。確認していない組み合わせは「未確認」と1行出して続ける（[tapir_features.py](src/ashiba/tapir_features.py)）。
  他バージョンではTapirコマンドの応答形式差分に注意（実機の落とし穴メモは
  `tapir_adapter.py` 冒頭のdocstringに集約）
- 本ツールの出力は計画作成参画者（有資格者）が確認する前提の下書き
